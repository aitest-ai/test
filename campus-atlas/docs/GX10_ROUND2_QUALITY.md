## 本輪目標
上一輪改善的是碰撞、導航、鏡頭與工具鏈，畫面風格仍是低多邊形示意。本輪只做一件事：
**讓使用者肉眼看得出畫面變好**，同時不犧牲上一輪的碰撞／導航／FPS。

## 硬性原則（延續，不可違反）
- 未經證實的尺寸、顏色、材質一律標「示意」。AI 生成的紋理只能標為「原創生成材質（示意）」，不得宣稱是東新國小實景照片或實測色票。
- 優先順序：不穿牆 > 比例正確 > 渲染穩定 > 視覺美化。美化不得破壞前三項。
- 參考站只當技術參考，不複製其美術與模型。
- 只在本分支工作；需要 sudo、新增大量下載（> 1 GB）前，先停下來告訴使用者。
- 不部署 Vercel。預覽部署由使用者決定；只在紀錄裡回報「本機如何開啟」。
- 每個階段完成都要跑 `npm test` 與 `tests/dx.browser.py`，不得退步；FPS 不低於上一輪最終數字的八成（GPU vsync 最低 ≥ 48；`--uncap` 最低 ≥ 1000；SwiftShader 最低 ≥ 8）。

### B 圖片型紋理接進材質庫 — 完成（2026-10-18）
**做法**
- **材質庫**（`src/materials/library.js`）：紋理加上 `image` 區塊就是圖片型紋理。欄位：
  - `src`：圖檔名，放在 `assets/textures/`，由 Vite 打包；單檔版會內嵌。
  - `repeatMeters`：一張貼圖代表幾公尺，可給數字或 `[u, v]`。
  - `anisotropy`：各向異性過濾。
  - `colorSpace`：預設 `"none"`。
  - `compose`：選用。先把圖片鋪到 Canvas，再疊一層程式化圖樣（新產生器 `joints`，畫分割縫與圓孔）。
- **比例**：幾何 UV 本來就以世界公尺計（`Batch`：1 UV＝1 m），所以 `texture.repeat = 1 / repeatMeters`，比例固定，不會隨牆面大小拉伸。
- **色彩空間**：專案關閉 ColorManagement、線性輸出。程式化 Canvas 紋理是照原始像素值取樣、原樣輸出，圖片紋理同樣用 `NoColorSpace`（原值取樣），所以 JPEG 的顏色會原樣出現在畫面上，與既有紋理一致。若設成 `srgb`，會先解碼成線性再線性輸出，畫面會偏暗，只有改用色彩管理時才該用。
- **載入與退回**：
  - 每張圖片型紋理先用原本的程式化版本（同一筆 `gen`/`p`）立即顯示，所以首幀與載入時間不必等圖片。
  - 圖片載入後換上：沿用同一個 Texture 物件，先 `dispose()` 釋放 GPU 端舊尺寸的儲存再換圖，材質與 shader 都不必重接。
  - 載入失敗時一直使用程式化備援，並印出 `console.warn`（例：「圖片 brick_red.jpg 載入失敗，紋理 brick 改用程式化備援」），不會白屏。
- **驗證**：`validateSpec` 會檢查 src 副檔名、圖檔存在（Node 端）、repeatMeters、colorSpace、anisotropy、compose／overlay 產生器、需有程式化備援。使用圖片型紋理時，`evidence` 必須含「原創生成材質（示意）」。
- **戶外鋪面**：東新場景的戶外地面是不受光的平面圖底圖，沒有使用 `pave` 材質。因此新增材質角色 `ground.detail`，在底圖 shader 疊一層以世界公尺鋪的鋪面細節，規則如下：
  - 只作用在底圖的鋪面色上：低彩度、非綠、非深色線條。草地、跑道、球場保留原色。
  - 細節值除以貼圖平均色，只加明暗紋理、不改色調；遠處經 mipmap 平均後自然淡出。
  - 只有圖片載入成功才開啟。換膜沒有圖片時，地面與原本完全相同。
- **交付貼圖**：`tools/comfyui/prep_textures.py` 把 1024² 原圖做成 512² JPEG：
  - 3×3 環狀拼貼後再縮圖，邊緣仍可無縫拼貼；
  - 平均色對齊原本程式化紋理的底色，換上後整體色調不變、只多了細節；
  - 混凝土氣孔淡化（第一版氣孔過黑，柱子近看像破洞）；
  - 磨石子對比降到 0.55（第一版顆粒過碎過暗）。

**過程中的退步與修正**：第一版在 SwiftShader 下載入時間從 4.3 s 變成 7.8 s，FPS 最低降到 7.6，低於門檻。
- **量測**：`applyImage` 共花 2.3 s，其中木門 1.15 s，而木門根本沒有合成步驟。
- **原因**：GPU 加速的 Canvas 在 `drawImage`／`getImageData` 時要和 GPU 程序同步，首幀編譯 shader 期間會被卡住。
- **修正**：合成與取平均色改用 CPU 端 Canvas（`willReadFrequently`），並在換圖前先 `img.decode()`。每張降到 2–4 ms，SwiftShader 載入回到 4.6 s。
